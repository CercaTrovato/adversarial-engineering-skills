# Adversarial Engineering Skills

**계획에 반례를 제시하고, 변경 사항을 검토하고, 결과를 증거로 확인합니다.**

[English](../README.md) · [简体中文](README.zh-CN.md) · [繁體中文](README.zh-TW.md) · [日本語](README.ja.md) · 한국어

코딩 에이전트를 위한 엔지니어링 관리 스킬입니다. 실제 프로젝트의 반례 중심 검토 방식을 추적 가능한 세 단계 품질 관문으로 정리했습니다. 검토자는 구체적인 실패 경로를 제시하고, 주 에이전트는 각 문제를 수정하거나 증거를 들어 기각합니다.

## 세 가지 관문

1. **계획 검토**: 본격적인 구현 전에 제약, API와 데이터 계약, 권한, 상태 전이, 누락된 사용 경로, 과도한 설계를 확인합니다.
2. **변경 검토**: 하나의 구현 단위가 끝나면 병합 전에 실제 diff와 영향을 받는 동작을 검토합니다. 필요한 경우 보안 관점의 검토를 추가합니다.
3. **인수 검증**: 완료를 선언하기 전에 현재 실행 결과나 산출물 점검으로 주장을 뒷받침하고, 확인하지 못한 범위를 밝힙니다.

작은 변경에는 간단한 점검을, 위험도가 높은 변경에는 독립적인 관점과 개별 검증 가능한 작업 단위를 적용합니다. 자체 검토는 명시적으로 표시하며 프로젝트가 요구하는 독립 검토를 대신할 수 없습니다. 해결되지 않은 차단 문제가 있으면 관문을 통과할 수 없습니다. 이 스킬은 배포나 공개 권한을 부여하지 않습니다.

## 설치

Git과 Node.js/npm을 준비한 뒤 대상 프로젝트에서 실행합니다.

```sh
npx skills add CercaTrovato/adversarial-engineering-skills --skill adversarial-engineering
```

대화형 설치에서 에이전트를 선택합니다. `-a claude-code`, `-a codex`, `-a cursor`로 대상을 지정하고, `--copy`로 심볼릭 링크를 피하며, `-g`로 사용자 범위에 설치할 수 있습니다. 다른 에이전트, 수동 설치, 제거 방법은 [설치 안내](INSTALL.md)를 참고하세요. 지원 범위는 외부 Skills CLI의 현재 목록을 따르며, 모든 에이전트에서의 실제 동작 검증을 뜻하지 않습니다.

## 사용

> 이 변경에 adversarial-engineering을 사용하세요. 구현 전에 계획을 검토하고, 구현 후 diff를 검토하고, 완료 전에 인수 조건을 검증하세요. 각 지적 사항의 처리 결과와 증거, 검증하지 못한 범위를 알려 주세요.

검토만 원한다면 “파일을 수정하지 마세요”라고 덧붙이세요. 유효한 증거가 있는 점검을 반복하지 않고, 수정된 문제와 관련된 항목만 재검토합니다. 추가 검토에는 새로운 증거나 실질적인 수정이 필요합니다.

[영문 SKILL.md](../skills/adversarial-engineering/SKILL.md)가 공식 지침입니다. 이 페이지는 소개와 설치 안내입니다. 무결점 보증이나 자동 CI 관문이 아닙니다. [검증 범위](VALIDATION.md), [기여 안내](../CONTRIBUTING.md), [MIT 라이선스](../LICENSE)를 확인하세요. 원어민 교정을 환영합니다.
