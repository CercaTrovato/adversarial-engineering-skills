# 對抗式工程管理技能

**質疑計畫，審查變更，以證據證明結果。**

[English](../README.md) · [简体中文](README.zh-CN.md) · 繁體中文 · [日本語](README.ja.md) · [한국어](README.ko.md)

這是一套供程式開發 Agent 使用的工程管理技能，將專案中的對抗式自我檢查實務整理為三道可追溯的品質關卡。審查者必須指出具體的失敗路徑，主要 Agent 則逐項修正，或以證據說明駁回理由。

## 三道關卡

1. **計畫檢查**：開始實質開發前，檢查限制、介面與資料契約、權限、狀態轉換、遺漏的使用端及過度設計。
2. **變更審查**：每個完整批次完成後、合併前，審查實際 diff 與受影響行為；涉及安全邊界時加上專項審查。
3. **驗收查證**：宣稱完成前，以當前執行結果或產出檢查支持結論，並交代尚未檢查的部分。

小變更採取小規模檢查；高風險變更採取獨立視角與可分別驗收的批次。自行審查必須明確標示，不能取代專案要求的獨立審查。未解決的阻塞項目不能視為通過。本技能不授予部署、發布或其他外部操作權限。

## 安裝

安裝 Git 與 Node.js/npm 後，在目標專案目錄執行：

```sh
npx skills add CercaTrovato/adversarial-engineering-skills --skill adversarial-engineering
```

透過互動介面選擇 Agent；可加上 `-a claude-code`、`-a codex` 或 `-a cursor` 指定目標，使用 `--copy` 避免符號連結，使用 `-g` 安裝至使用者範圍。其他 Agent、手動安裝及移除方式見[安裝指南](INSTALL.md)。相容性依第三方 Skills CLI 的現行清單為準，不代表所有 Agent 都經過端到端驗證。

## 使用

> 請用 adversarial-engineering 處理此變更：開發前挑戰計畫，完成後審查 diff，交付前查證驗收結論。記錄每項發現的處置與證據，並說明尚未驗證的部分。

只需審查時，補充「不要修改檔案」。既有證據仍有效時不重複測試；只複查已修改的相關問題，後續審查須有新證據或實質修訂。
