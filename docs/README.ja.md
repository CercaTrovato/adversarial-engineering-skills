# Adversarial Engineering Skills

**計画を疑い、差分をレビューし、結果を証拠で確かめる。**

[English](../README.md) · [简体中文](README.zh-CN.md) · [繁體中文](README.zh-TW.md) · 日本語 · [한국어](README.ko.md)

コーディングエージェント向けのエンジニアリング管理スキルです。実際の開発で使われた反証型レビューを、追跡可能な三つの品質ゲートに整理しました。レビュー担当者は具体的な失敗経路を示し、主担当エージェントは修正するか、証拠を添えて指摘を退けます。

## 三つのゲート

1. **計画**：本格的な実装前に、制約、API・データ契約、権限、状態遷移、影響先の漏れ、過剰設計を検討します。
2. **変更**：まとまった実装単位が完成した後、マージ前に実際の差分と影響する動作を確認します。必要に応じてセキュリティ面もレビューします。
3. **受け入れ**：完了を宣言する前に、現在の実行結果や成果物の確認で主張を裏付け、未確認事項を明示します。

小さな変更には小さな確認を、高リスクの変更には独立した視点と個別に検証できる作業単位を使います。自己レビューは明示し、プロジェクトが必須とする独立レビューの代わりにはしません。未解決のブロッカーがあるゲートは通過できません。このスキルはデプロイや公開を許可するものではありません。

## インストール

Git と Node.js/npm を用意し、対象プロジェクトで実行します。

```sh
npx skills add CercaTrovato/adversarial-engineering-skills --skill adversarial-engineering
```

対話形式でエージェントを選択できます。`-a claude-code`、`-a codex`、`-a cursor` で指定し、`--copy` でシンボリックリンクを避け、`-g` でユーザー単位にインストールできます。ほかのエージェント、手動導入、削除は[インストールガイド](INSTALL.md)を参照してください。対応範囲は外部の Skills CLI の現行一覧に基づき、全エージェントでの動作検証を意味しません。

## 使い方

> この変更に adversarial-engineering を使ってください。実装前に計画を検討し、変更後に差分をレビューし、完了前に受け入れ条件を検証してください。各指摘の対応と証拠、未検証の範囲を示してください。

レビューのみなら「ファイルを変更しないでください」と指定します。有効な証拠がある確認を繰り返さず、修正に関連する指摘を再確認します。追加のレビューには新しい証拠か実質的な修正が必要です。
