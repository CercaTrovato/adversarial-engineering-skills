# Contributing

Keep the English SKILL.md canonical and compact. Propose changes with a realistic failure case, the smallest instruction change that addresses it, and the behavior that would demonstrate improvement. Do not add universal gates based on a single project's preferences.

Review scope, authorization, evidence quality, finite stopping conditions, and behavior when independent agents or runtime access are unavailable. Preserve stronger repository policies. Do not introduce vendor-specific tools as mandatory dependencies.

Translations are localized overview and installation pages. Keep their semantics aligned with the English README; retain commands and identifiers unchanged. Native-speaker corrections are welcome. Never claim a translation has received native-speaker review unless it has.

Use synthetic examples. Do not submit credentials, private repository snippets, customer data or identifying incident details. Before a release, inspect Markdown links, skill discovery, isolated installation and realistic review behavior. Record the scope and limits in docs/VALIDATION.md.
